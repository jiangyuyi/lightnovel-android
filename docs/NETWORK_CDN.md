# 网络、CDN 与代理路径排障记录

本项目依赖轻之国度当前公开的 Web BFF；没有稳定 SDK 或对代理兼容性的正式承诺。此文档记录已验证的事实和后续排障边界，不将某次解析得到的 CDN 地址写入代码。

## 2026-09：封面与插画同时加载失败

- 站点接口仍返回正常的封面 `cover_url` 和正文插画 URL，并非资源字段变更。
- 旧实现把站点域名固定映射到过时的 Cloudflare IP；站点当时已转向其他 CDN。手机上出现 TLS 握手失败与 `net_error -101`，浏览器经系统 DNS 可以打开同一资源。
- 修复为所有 Cronet 引擎跟随系统 DNS，移除静态 HostResolverRules/IP。自动协议、HTTP/2、HTTP/1.1 只在可重试的传输错误时有限尝试；不把业务错误当作 CDN 错误，不自动重发领取等写操作。

## 2026-10-12：搜索看似不可用

- 网站的搜索页面及 `POST https://www.lightnovel.fun/api/pc-proxy/api/bff/apk-search-result-v1` 仍可使用。同一请求包含 `q`、`page=0`、`pageSize=20`、`sort=relevance` 等完整字段时，搜索“败犬女主”返回 `code=0` 和 5 条结果。
- 旧网络层遇到主站连接失败，将搜索结果请求改送 `https://api.lightnovel.fun/proxy/api/bff/apk-search-result-v1`。此路径虽然 HTTP 200，却返回业务 `code=3`、`pageSize` 校验错误，不能视为兼容的备用代理。
- `POST https://api.lightnovel.fun/pc-comment-proxy/api/bff/apk-search-result-v1` 在相同请求体下返回 `code=0` 和同样 5 条结果。1.7.1 仅将**搜索结果**的连接失败回退改到此路径；搜索分类原路由可用，未改动。业务错误不触发代理切换。
- 真机复现期间曾看到 Chromium `net_error -101`。在网络恢复后旧版也能得到结果，因此这是“主站连接波动 + 不兼容备用路径”造成的可靠性问题，而非搜索接口整体失效或域名必须固定 IP。
- 1.7.1 本地 83 项单元测试、Lint 和签名构建通过；证书 SHA-256 与既有发布一致。手机已保留数据覆盖升级。测试期间也遇到代理 App 后台被杀及网络重置，须在代理稳定时用未缓存关键词验证，不能用旧结果列表代替实时请求验收。

## 后续排障顺序

1. 先验证手机网络与系统 DNS；记录具体页面、请求路径、HTTP 状态、业务码和连接错误。不要把单次超时解释为 API 改名。
2. 用相同请求体分别验证主路径和候选备用路径。HTTP 200 仍须检查业务 `code`、返回结构与实际数据。
3. 只为已验证兼容的只读请求配置备用代理；写请求不自动重试或切路由，以免重复领取或扣费。
4. 保留缓存内容并展示刷新状态；对封面和插画核对服务器返回的原始 URL，不猜测替换资源主机。
5. 不固定 CDN IP、不写死当前解析结果、不输出用户凭据。若站点接口再次变化，更新此文档与对应路由回归测试。
