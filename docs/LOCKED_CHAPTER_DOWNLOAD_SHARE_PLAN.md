# 锁定章节、正文链接与图书分享实施计划

> 文档状态：已确认并完成实施与真机验收  
> 调研日期：2026-09-02  
> 版本：1.4.1

## 1. 目标与本轮边界

本版本计划解决三个相互关联的问题：

1. 目录中的“锁定”章节可以像“开始 / 继续阅读”一样正常尝试打开，不再因目录 UI 的本地判断而完全无响应。
2. 阅读正文保留并展示网页中的链接，支持站内直接下载、需要轻币的下载动作，以及站外网盘链接；同时在付款前后查询并展示轻币余额。
3. 图书详情页提供网页原始链接的复制与系统分享能力。

本轮不会实现 EPUB 阅读器、整本批量抓取、网盘文件代下、轻币充值、自动投币、后台静默购买，也不会绕过网站已有的登录、权限、轻币或下载限制。

## 2. 已确认现状与问题根因

### 2.1 参考对象

- 登录后的网页阅读记录中，第一本书为《才女的侍从[台版]》，书籍 ID 为 `11534`，原始网页为 `https://www.lightnovel.fun/book/11534`。
- 当前账号页能正常展示“轻币”，调研时余额为 `370`。App 已通过 `api/bff/my-home-v1` 获取并在“我的”页展示该字段，因此余额查询能力可复用，不需要另造账户接口。

### 2.2 “锁定章节”无响应的直接原因

当前目录代码使用：

```kotlin
.clickable(enabled = !chapter.locked) { onRead(chapter.id) }
```

也就是说，只要目录接口返回 `locked=true`，App 就直接禁用点击。与此同时，“开始 / 继续阅读”调用 `api/bff/reader-bootstrap-v1` 得到章节 ID 后直接进入阅读器，并不检查该字段。这正是同一本书从两个入口表现不一致的原因，并非 Android 导航偶发失效。

目前解析层还把 `locked=true` 和 `unlocked=false` 合并为同一个布尔值。这样会丢失站点原始语义，也无法区分以下情况：

- 章节被作者/编辑锁定修改，但仍可公开阅读；
- 章节需要登录、轻币或其他权限解锁；
- 章节处于隐藏、审核或暂不可用状态；
- 旧接口只保留了兼容字段，但阅读接口才是最终权限判定者。

### 2.3 对“锁定”设计意图的推测

目前最可能的设计意图是：目录字段描述章节的站点状态或编辑锁，而不是“客户端必须禁止进入”的最终访问权限。依据是同一登录态下，网页/App 的继续阅读入口可以取得该章节并打开正文；如果它是绝对不可读章节，阅读入口也应被服务端拒绝。

这一结论在正式实现前仍要做一次只读验证：保存参考书目录与章节详情的脱敏响应，对照网页目录元素和实际阅读请求。如果服务端确实把 `locked` 用作付费/权限提示，目录仍应允许点击，但点击后进入明确的登录、购买或不可用提示，而不是没有任何反馈。无论字段最终语义是哪一种，“由目录 UI 提前静默禁用”都不是合适行为，章节详情接口应是访问权限的最终判定来源。

实施期只读验证结果：网页中的公开章节为 `accessType=public`、`locked=false`、`unlocked=true`；EPUB 参考章节 `261248` 为 `accessType=coin`、`locked=true`、`unlocked=false`、`coinPrice=20`。网页目录对两类章节都提供可点击的 `/reader/{bookId}/{chapterId}` 链接，进入轻币章节后才显示“是否使用 20 轻币解锁本章”。因此目录中的锁图标表示“进入后需要解锁”，不是“目录禁止点击”。

### 2.4 正文链接丢失的原因

当前 `ReaderContentParser` 只识别段落和 `<img>`。`<a>` 标签会在去除 HTML 标签时被删除，只留下链接文字，因此：

- 直接下载地址无法点击；
- 站外网盘地址无法打开；
- 由链接或 `data-*` 属性承载的轻币购买动作无法识别；
- 纯文本正文中的完整 `http/https` 地址也不会生成可点击对象。

## 3. 实施前的 API 与样本确认门槛

正式编码的第一步是只读记录三类真实样本，不执行付款或下载：

1. 参考书 `11534`：目录响应中的 `locked/unlocked/status` 等原始字段、章节详情响应、网页目录实际链接。
2. EPUB 分区：至少一个直接下载样本、一个需要轻币的样本、一个站外网盘样本。
3. 非 EPUB 分区：至少一个包含下载或投币链接的正文样本。

对样本记录以下内容，并将敏感值脱敏后放入测试夹具：

- 请求路径、HTTP 方法、必要参数和登录要求；
- 链接的 `href`、可见文字、`target/rel` 及与动作有关的 `data-*` 属性；
- 支付前的价格查询方式、支付 API、成功/失败业务码、是否存在订单或幂等字段；
- 下载响应的重定向、`Content-Type`、`Content-Disposition`、文件名和是否要求一次性签名；
- 付款后正文或下载地址是否需要重新请求。

约束：

- 调研阶段只观察网络和页面，不点击“投币/确认支付”，不实际保存文件。
- 不把 `security_key`、Cookie、签名下载 URL 或网盘提取码写入 Git、日志、截图和测试数据。
- 如果网页动作不是公开 API，而是表单、一次性令牌或验证码流程，优先在受控浏览器中完成，不猜测或复刻不完整协议。

## 4. 锁定章节改造方案

### 4.1 数据模型

用保留原始语义的访问状态替换单一 `locked` 判断，建议模型为：

```text
ChapterAccessState
├─ Readable              明确可读
├─ RequiresLogin         需要登录
├─ RequiresCoin          需要轻币或购买
├─ Unavailable           隐藏、审核中或服务端明确禁止
└─ UnknownMarkedLocked   只有模糊的 locked 标记，仍允许尝试打开
```

同时保留原始 `locked`、`unlocked`、状态码和价格字段，兼容缓存迁移。若真实响应没有足够信息，则目录默认使用 `UnknownMarkedLocked`，而不是直接禁用。

### 4.2 交互规则

- 所有具有有效 `chapter_id` 的目录项都可点击。
- 点击后由 `get-chapter-detail` 的实际响应决定结果：
  - 返回正文：正常进入阅读器；
  - 会话过期/需要登录：显示登录引导，登录后只重试一次；
  - 需要轻币：显示价格和余额确认页，用户确认前不发起支付；
  - 审核、隐藏或无权限：展示服务端可读错误，不进入空白页。
- 目录上的状态标识改为中性样式。只有确认是付费章节时显示“需轻币”；模糊 `locked` 不再用红色“锁定”暗示绝对不可读。
- “开始 / 继续阅读”和目录点击共用同一个 `openChapter` 流程，避免再次出现分支逻辑漂移。

### 4.3 错误与缓存

- 不缓存一次性的权限失败为永久不可读。
- 成功解锁后失效该章节详情、目录状态和账户余额缓存，并立即重新请求。
- 旧版缓存中的 `locked=true` 迁移为 `UnknownMarkedLocked`，不能继续被当作禁用条件。

## 5. 正文链接模型与安全策略

### 5.1 解析结果

为阅读器增加可分页、可点击的链接块/行内片段：

```text
ReaderLink
├─ label                 页面显示文字
├─ normalizedUrl         规范化后的绝对 URL
├─ kind                  DirectDownload / ExternalWeb / InternalWeb / CoinAction / Unknown
├─ host                  用于确认弹窗展示
├─ suggestedFileName     可选
├─ price                 可选轻币价格
└─ actionMetadata        仅保留已验证的非敏感站点参数
```

解析范围包括：

- HTML 中的 `<a href>` 及已验证的动作属性；
- 相对地址，统一以 `https://www.lightnovel.fun/` 为基址；
- 纯文本中完整的 `https://` 或 `http://` 地址；
- 链接内嵌图片时，图片仍显示，并提供可访问的点击语义。

正文中的标题、普通段落与图片行为保持不变。分页计算需要把链接文字按普通文字测量，避免新增链接后页码和点击热区错位。

### 5.2 URL 安全规则

- 只接受 `https`；对网站真实存在但仅提供 `http` 的站外链接，先展示风险确认，再交给系统浏览器处理。
- 拒绝 `javascript:`、`data:`、`file:`、`content:`、`intent:` 和未知 scheme。
- 站内动作只信任精确的 `lightnovel.fun` 主机和已经确认的路径，不使用字符串“包含域名”判断。
- 展示站外主机名，点击网盘链接时明确提示“将离开 App”。
- 链接文字写着“投币”但指向站外域名时，绝不当作站内支付；支付动作必须同时满足站点来源、已知接口和结构化参数。
- 不在异常、埋点或崩溃日志中记录带签名、令牌或提取码的完整 URL。

## 6. 下载功能方案

### 6.1 两种链接的处理

| 链接类型 | App 行为 |
| --- | --- |
| 站内直接文件/已签名下载 | 显示文件名、来源、大小（可取得时），由用户确认保存位置后下载 |
| 站内下载落地页 | 打开站内确认页或调用已验证 API，不把 HTML 错存为 EPUB |
| 站外网盘 | 显示目标域名并调用 Android 系统浏览器/对应网盘 App；App 不代抓、不解析提取码、不绕过网盘登录 |
| 无法分类的网页链接 | 作为普通网页链接打开，不自动下载或支付 |

### 6.2 Android 下载实现

- 使用系统文件创建器 `ACTION_CREATE_DOCUMENT` 让用户选择位置，不申请全盘存储权限。
- 对无需登录的普通下载可交给系统下载器；对需要 App 会话或短时签名的站内文件，扩展 Cronet 为流式写入 `ContentResolver`，避免把整本 EPUB 读入内存。
- 正确处理重定向、取消、超时、网络切换、重复文件名、未知长度和存储空间不足。
- 只在 `Content-Type`、扩展名或 `Content-Disposition` 符合预期时保存；如果返回 HTML/JSON 错误页，解析业务错误并删除未完成文件。
- 下载中显示进度和取消入口；完成后提供“打开文件”，由系统选择 EPUB 阅读器。
- 进程被杀后的第一版不承诺自动续传，但必须保证临时文件可清理、失败不会显示为成功。

## 7. 轻币查询与支付方案

### 7.1 余额

- 复用 `api/bff/my-home-v1` 和现有 `AccountProfile.coin`。
- 在正文的付费下载卡片及确认弹窗中展示“价格、当前轻币、支付后预计余额”。
- 提供显式刷新按钮；余额为缓存时标出更新时间，进入支付确认前强制刷新一次。
- 站点术语统一显示为“轻币”，可在首次说明中注明“即用户所说的积分”。

### 7.2 支付流程

```text
点击付费链接
  → 检查登录
  → 查询商品/附件状态与真实价格
  → 刷新轻币余额
  → 展示二次确认
  → 用户明确点击“支付 X 轻币”
  → 单次提交支付
  → 查询结果/余额并刷新章节
  → 展示下载入口
```

关键约束：

- 价格以支付前服务端返回为准，正文文字只能作为提示，不能作为扣款参数。
- 扣款请求视为非幂等操作：按钮提交后立即锁定，不做传输层自动重试，不因超时再次扣款。
- 如果真实接口提供订单号、nonce 或幂等键，必须完整使用；如果没有，超时后先查订单/权限/余额，不能直接重发。
- 余额不足时只提示所需与缺少数量，不引导伪造余额或绕过限制。
- 付款成功但下载地址刷新失败时保留“重新获取已购下载”入口，不再次付款。
- 任何自动化测试只覆盖模拟服务器；真机支付验收必须由用户看到金额后手动确认。

## 8. 图书网页链接分享

### 8.1 链接生成

- 图书详情页的规范链接固定为 `https://www.lightnovel.fun/book/{bookId}`。
- 使用当前详情页的真实 `bookId`，不使用搜索标题拼接，也不复制 API 地址或阅读进度章节地址。
- 只允许正数 ID，异常状态下禁用分享并给出提示。

### 8.2 UI

- 在图书页顶部操作区增加分享图标。
- 点击后至少提供“复制网页链接”；复制成功显示短提示并包含完整 URL。
- 同一入口可提供“分享到其他应用”，使用 Android 系统分享面板，正文包含书名和规范链接。
- 返回、刷新和书架操作不受影响；TalkBack 能读出“分享图书网页链接”。

## 9. 代码改动范围

预计涉及以下模块：

| 模块 | 主要改动 |
| --- | --- |
| `core/model` | 章节访问状态、正文链接、下载/购买状态模型 |
| `core/network` | 保留目录原始状态字段；增加已验证的商品查询、支付与流式下载调用；响应头支持 |
| `core/data` | 统一章节打开流程、余额刷新、支付并发保护、购买后缓存失效 |
| `feature/book` | 目录可点击与状态提示、复制链接和系统分享 |
| `feature/reader` | `<a>`/纯文本 URL 解析、链接样式、点击分流、付费下载卡片 |
| `core/ui` 或新 `feature/download` | 外链确认、保存位置、进度、错误与完成状态 |
| 测试与文档 | 脱敏夹具、解析/安全/状态机测试、README 与中文 Changelog |

不引入 WebView 保存登录态；优先沿用当前原生页面和 Cronet 网络层。只有真实支付动作必须依赖网页的一次性脚本且无法安全复刻时，才将该动作交给系统浏览器，并在实现记录中说明限制。

## 10. 实施顺序

1. **协议确认**：完成第 3 节的只读样本采集，补齐准确 API 表和脱敏夹具。
2. **锁定章节修复**：重构状态模型和统一打开流程，先让参考书目录与继续阅读一致。
3. **链接解析**：保留 `<a>` 和纯文本 URL，完成安全分类及阅读器点击热区。
4. **普通链接与网盘**：先实现无扣款风险的站内网页、直接文件和站外网盘处理。
5. **余额与付费**：接入余额刷新、商品预检、确认弹窗、单次支付和购买后刷新。
6. **图书分享**：增加复制规范链接与系统分享。
7. **自动验证**：单元测试、Lint、Debug/Release 构建。
8. **真机验证**：先做无写入流程，最后由用户手动确认一次低额真实支付；未经确认不扣轻币。
9. **发布准备**：更新版本号、README 和全中文 Changelog，再按既有 PR/CI/Release 流程发布。

## 11. 测试矩阵与验收标准

### 11.1 自动测试

- 目录同时含 `locked`、`unlocked`、未知状态和付费状态时，解析不丢字段。
- `locked=true` 且章节详情可读时，目录点击能进入正文。
- 章节详情返回登录、余额不足、付费、隐藏和普通网络错误时，提示准确且不会出现空白页。
- HTML 链接、相对链接、中文实体、链接内图片、纯文本 URL 和跨分页链接均正确解析。
- 危险 scheme、伪造子域名、站外“投币”文案不能触发站内支付。
- 下载响应为 EPUB、重定向、HTML 错误、未知大小、取消和写盘失败时状态正确。
- 支付按钮防连点；超时不自动重试；成功后刷新余额、权限与正文缓存。
- 图书 ID `11534` 生成的链接严格等于 `https://www.lightnovel.fun/book/11534`。
- `testDebugUnitTest`、`lintDebug`、`assembleDebug` 和签名 Release 构建通过。

### 11.2 真机验收

1. 从“我的 → 阅读记录”打开第一本《才女的侍从[台版]》，展开目录，原先标记锁定的章节可点击并与“开始 / 继续阅读”表现一致。
2. EPUB 样本中的直接下载链接可选择保存位置、显示进度并用外部 EPUB 阅读器打开。
3. EPUB 与非 EPUB 样本中的站外网盘链接均显示真实域名并能交给浏览器/网盘 App。
4. 付费样本在确认前能显示真实价格与最新轻币余额；取消不扣款；一次确认只产生一次扣款；成功后余额和下载权限同步更新。
5. 未登录状态能正确引导登录，登录后回到原动作，但不会自动付款。
6. 图书页复制得到精确网页地址，系统分享面板内容包含书名和地址。
7. 返回阅读、翻页、下一章、插图、正文缓存和书架功能无回归。

## 12. 风险与回退

- **站点接口变化**：支付与签名下载通过独立 Repository 接口和脱敏夹具隔离；业务码未知时停止并显示原始可读错误，不猜测成功。
- **重复扣款**：支付请求不走现有网络自动重试；使用服务端幂等字段或支付后状态查询。
- **缓存过期**：稳定正文可继续本地缓存，但价格、余额、购买状态和短时下载 URL 不进入七天正文缓存。
- **大文件内存占用**：下载必须流式写盘，不复用当前会把完整响应读入 `ByteArray` 的图片接口。
- **恶意链接**：严格 scheme/host 校验，站外统一确认，站内支付仅允许已验证路径。
- **无法安全复刻网页支付**：回退为打开站点原始页面让用户完成购买，购买后返回 App 刷新；绝不使用猜测参数扣款。

## 13. 已确认的实施决策

以下默认选择已由用户确认：

1. 版本号采用 `1.4.1`。
