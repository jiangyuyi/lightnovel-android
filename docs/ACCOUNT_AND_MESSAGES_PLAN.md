# 1.1.0 用户功能与 1.2.0 消息中心实施计划

## 1. 目标与版本边界

本轮按两个可独立验收的里程碑推进，必须先完成并在真机验证 1.1.0，再开始 1.2.0：

- **1.1.0 用户中心**：个人概览、关注、粉丝、阅读记录、发布管理。
- **1.2.0 消息中心**：未读汇总、回复、@、点赞、新粉丝、系统通知、私信会话与只读消息线程。

实施状态（2026-08-08）：

- 1.1.0 已完成真机验收，并通过 PR #4、标签 `v1.1.0` 和 GitHub Release 发布。
- 1.2.0 已完成实现、单元测试、Lint、Debug 构建和登录真机只读验收；现有账号无未读通知，因此未执行“标为已读”写入式验收。
- 真机确认回复、@、点赞、新粉丝空状态，系统历史通知列表，以及私信会话和只读线程；站点会话接口可能不返回最后消息摘要，App 使用中性入口提示。

站点的内容编辑、发帖、私信发送、消息内直接回复会产生公开内容或对外消息，本轮先保留为后续能力；1.1.0 的“发布管理”提供作品列表、状态、审核进度和作品跳转，不在 Android 端复制完整网页写作工作台。

## 2. 网站入口与 API 结论

网站登录后的主要入口为：

- `/me`：个人概览、书架、阅读记录、发布管理与设置。
- `/me/follows?tab=following`：关注列表。
- `/me/follows?tab=fans`：粉丝列表。
- `/messages?tab=reply`：消息中心。
- `/activity`：动态广场/关注动态。
- `/write`、`/write/book/{bookId}`：作者工作台。

以下路径均通过 `https://www.lightnovel.fun/api/pc-proxy/` 以 `POST application/json` 调用，登录接口都携带 `security_key`。

### 2.1 1.1.0 API

| 能力 | API | 请求重点 | 返回重点 |
| --- | --- | --- | --- |
| 个人概览 | `api/bff/my-home-v1` | `security_key` | `profile/user`、等级、签名、轻币、粉丝/关注/发布数量 |
| 关注列表 | `api/bff/user-following-v1` | `uid`, `page`, `pageSize`, `security_key` | `list/items`、分页、用户关系状态 |
| 粉丝列表 | `api/bff/user-followers-v1` | 同上 | 同上 |
| 关注/取消关注 | `api/bff/toggle-user-follow-v1` | `uid`, `action: follow/unfollow`, `security_key` | `followed`/关系状态 |
| 阅读记录 | `api/bff/history-v1` | `page`, `pageSize`, `security_key` | 书籍、最后阅读章节、阅读时间、是否仍在书架 |
| 删除单条记录 | `api/new-content-read/delete-book-history` | `book_id`, `security_key` | 操作状态 |
| 发布作品列表 | `api/bff/longform-book-list-v1` | `page`, `pageSize`, `security_key` | 作品状态、字数/卷章数、更新时间、审核状态 |

响应兼容原则：

- 用户 ID 兼容 `uid/user_id/id`；头像兼容 `avatar/avatar_url/avatarUrl`。
- 用户关系兼容 `followed/is_followed/is_following/relation.followed`。
- 阅读时间兼容 `read_at/last_read_at/history.updated_at/read_state.last_read_at`。
- 最后章节兼容 `last_read_chapter_id/history.chapter_id/read_state.last_read_chapter_id`。
- 发布列表兼容 `list/cards/items`；状态由 `meta_json.serialize_status`、`status`、审核字段共同映射。
- 分页兼容 `pagination/page_info/pageInfo`，同时接受 `page_size/pageSize/size` 与 `has_more/hasMore/has_next`。

### 2.2 1.2.0 API

| 能力 | API | 请求重点 |
| --- | --- | --- |
| 未读汇总 | `api/bff/message-unread-v1` | `security_key` |
| 回复与 @ | `api/bff/message-replies-v1` | `filter: mention` 仅用于 @；`page` 为 0 起；`page_size` |
| 点赞 | `api/bff/message-likes-v1` | `page` 为 0 起；`page_size` |
| 新粉丝 | `api/bff/message-fans-v1` | 同上 |
| 系统通知 | `api/bff/message-system-v1` | 同上 |
| 私信会话 | `api/bff/dm-conversations-v1` | `page`, `page_size` |
| 私信线程 | `api/bff/dm-messages-v1` | `peer_uid` |
| 分类已读 | `api/bff/message-mark-read-v1` | `scope: category`, `category` |
| 私信已读 | `api/bff/dm-mark-read-v1` | 登录令牌与防重复字段 |

通知模型需要保留 `target_book_id`、`target_volume_id`、`target_chapter_id`、`target_dynamic_id`、评论/回复 ID 与各类 `target_url`。Android 端优先跳转可识别的书籍或章节；动态和评论精确定位在尚无原生页面时只展示内容，不构造猜测路由。

## 3. 1.1.0 设计

### 3.1 页面

1. “我的”升级为用户仪表盘：头像、昵称、UID、等级/用户组、轻币及关注/粉丝/发布数量。
2. 仪表盘提供“关注”“粉丝”“阅读记录”“发布管理”入口；已有“我的书架”保持原入口。
3. 关注/粉丝页共用列表组件和分页状态，展示头像、昵称、等级、签名、关系按钮。
4. 阅读记录显示封面、作品名、最后章节与时间；点击优先续读最后章节，不能定位时进入书籍详情；删除必须二次确认。
5. 发布管理显示封面、类型、连载/隐藏/草稿状态、审核进度、卷/章/字数和更新时间；点击进入公开书籍详情。

### 3.2 状态与错误

- 所有页面在未登录时显示统一登录引导。
- 首屏加载、加载更多和单项操作错误分开保存，避免一次关注失败清空列表。
- 关注操作使用进行中集合防止重复点击；成功后同步本地关系和计数。
- API 返回空列表时展示业务相关空状态，不把空数据误报为网络失败。
- 会话过期沿用现有会话恢复策略，不因瞬时网络错误清除本地令牌。

### 3.3 1.1.0 验收门槛

- 单元测试覆盖新增解析器的历史字段、空字段和分页兼容。
- `testDebugUnitTest`、`lintDebug`、`assembleDebug` 通过。
- 在已连接手机安装 1.1.0，确认当前登录态可恢复。
- 真机确认个人概览、关注、粉丝、阅读记录、发布管理均能加载；阅读记录可跳转正文；不在自动验证中执行关注/取消关注或删除。
- 只有上述验证通过后，才把默认版本切换到 1.2.0 并实现消息中心。

## 4. 1.2.0 设计

### 4.1 页面与导航

1. “我的”增加消息中心入口和总未读徽标。
2. 消息中心顶部使用可横向滚动分类：私信、回复、@、点赞、新粉丝、系统；每类显示独立未读数。
3. 通知卡显示来源用户/系统图标、标题、正文、引用内容、关联作品和时间，未读项使用明显底色。
4. 私信分类先展示会话列表；点击进入只读线程，显示对方信息、消息方向与时间。
5. 消息的可识别目标支持跳转到书籍详情或指定章节阅读；无法原生处理的目标不执行错误跳转。
6. 分类提供显式“全部标为已读”操作；避免仅浏览页面就自动改变站点状态。

### 4.2 本轮不做的消息写入

- 私信发送。
- 从通知卡直接回复评论/动态。
- 点赞、举报和动态评论。

这些能力涉及反骚扰规则、内容审核、引用作用域与失败回滚，应在后续版本单独设计和真机人工验收。

### 4.3 1.2.0 验收门槛

- 测试覆盖六类未读数、各类通知字段和私信会话/消息的兼容解析。
- `testDebugUnitTest`、`lintDebug`、`assembleDebug` 通过。
- 真机确认六类入口、空状态、加载更多、私信线程、书籍/章节跳转。
- 只在用户明确点击时验证“标为已读”，自动化冒烟测试不改变消息状态。

## 5. 已确认的其他登录功能与遗漏清单

网站前端还暴露以下登录能力，本轮处理策略如下：

| 功能 | 当前状态/计划 |
| --- | --- |
| 我的书架、加入/移出书架 | 已实现 |
| 阅读进度与阅读设置同步 | 已实现 |
| 个人资料编辑、头像、背景 | 未实现；后续账户设置版本 |
| 修改密码 | 未实现；后续账户安全版本 |
| 勋章中心、领取/兑换/佩戴、轻币 | 未实现；个人概览只展示已有信息 |
| 动态广场、发布动态、点赞/转发/评论 | 未实现；属于社区模块 |
| 书签 | 未实现；需要在阅读器设计段落/位置映射 |
| 完整作者工作台（新建/编辑/删除书、卷、章、草稿与图片） | 未实现；1.1.0 仅提供发布作品管理视图 |
| 作者申请与审核状态 | 未实现；可在作者工作台版本接入 |
| 公开用户主页、公开书架、屏蔽用户 | 未实现；关注列表先展示必要用户信息 |
| 评论发布、回复、点赞、举报 | 未实现；当前评论仍为只读 |
| 私信发送、通知内回复 | 1.2.0 明确暂缓，先完成安全的只读消息中心 |

优先级建议：1.2.0 之后先做“个人资料/账户安全”，再评估“社区动态”，完整作者工作台应单独立项，因为它包含上传、草稿恢复、审核和删除等高风险写操作。

## 6. 实施顺序与完成定义

1. 落盘本文档并以网站公开前端代码复核接口。
2. 新增模型、兼容解析、Repository 和测试。
3. 完成 1.1.0 页面与导航，版本号设为 `1.1.0`。
4. 构建并在手机上完成 1.1.0 只读冒烟验证。
5. 新增 1.2.0 消息模型、Repository、页面与导航，版本号设为 `1.2.0`。
6. 再次执行自动测试、构建和手机冒烟验证。
7. 更新 README 的已实现/暂缓功能和真机验证记录。

最终源码默认版本为 `1.2.0`；计划文档和 Git 历史保留 1.1.0 的独立验收结果。
