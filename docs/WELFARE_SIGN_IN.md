## 接口证据

从用户手机的官方安装包中只读检查得到接口路径；未提取官方 App 私有数据、账号令牌或签名密钥。安装包和调查截图只保存在被 Git 忽略的 `artifacts/official-coins/`，不分发官方代码或资源。

匿名 POST 实测确认现有 `https://www.lightnovel.fun/api/pc-proxy/` 能访问：

| 路径 | 用途与状态 |
| --- | --- |
| `api/bff/welfare-home-v1` | 返回 wallet、sign_in、earn_coin、tasks；匿名为 guest |
| `api/bff/welfare-sign-detail-v1` | 返回签到模块；匿名已验证 |
| `api/bff/claim-welfare-sign-v1` | 官方安装包中的签到领取路径；接入后需登录真机验证 |
| `api/bff/welfare-coin-records-v1` | 轻币记录；匿名返回业务码 8，本轮不接入 |

签到读取 home 的 `wallet.coin/today_coin` 和 `sign_in`，沿用本 App 的 `security_key`。不硬编码奖励金额、签到周期或活动键。只在 enabled、claimable 为真且 claimed 为假时允许手动领取；领取请求只传现有登录凭据，不自动签到，不自动重试写请求。

## 实施及验证计划

1. “我的”增加签到入口，轻币余额数字也可打开签到详情。
2. 展示服务器下发的奖励日列表、领取状态、余额和今日收益。
3. 领取后重新查询状态；网络超时也先查询，避免误判失败后重复领取。无法核实时禁用领取，要求刷新。
4. 退出详情刷新个人余额，清理领取前的个人概览缓存；每次打开及回到前台刷新签到状态，避免跨天沿用旧资格。
5. 补充解析与领取状态机测试，构建、检查并保留数据覆盖安装，核对官方 App 和本 App 的状态一致性。
6. 当前账号今日已领，只能验证已领状态；首次实际发奖需另一天由用户点击签到完成验收，不修改设备时间或伪造签到日期。

## 领取故障调查与候选修复（2026-09-27）

### 已确认的事实

- 本客户端领取出现 `ERR_QUIC_PROTOCOL_ERROR`；当时服务端返回的天数发生跳变，但余额没有对应增加。不能将该次请求判为领取成功。
- 同一登录态分别只读查询 Web 代理首页、官方 App 代理首页及签到详情，均返回新一轮第 1 天。官方 App 初始显示第 2 天，重启并完成网络加载后也显示新一轮第 1 天；不是本客户端把第 2 天自行计算成第 4 天。
- 用户说明期间官方版本更新可能重置了数据；重置原因未获服务端证据，不据此硬编码天数或补发奖励。
- 经用户明确允许，仅在官方 App 领取一次：成功提示 +159，今日收益从 18 变成 177。本客户端随后读到总余额从 486 变成 645、今日已领，第 1 天金额 159，与官方一致。

### 修复与安全边界

- 福利读写统一使用官方安装包中发现的 `https://api.lightnovel.fun/proxy/`；读查询的官方入口已真机验证。
- 早期尝试强制 HTTP/1.1，后续仍复现连接重置，未采用为最终方案。最终保留自动协议、HTTP/2、HTTP/1.1 三种连接方式，全部采用域名及系统 DNS；不强制一个协议，不固定 CDN IP。
- 按域名记住近期读取成功的连接方式，五分钟后失效；读取连接失败可尝试其他方式并进行一次有限的最终重试。领取前重新读取资格，确认连接可用，然后领取只尝试一次；若预先读取失败，不发送领取请求。
- 根据用户提供的历史 CDN 故障记录，已彻底移除旧 Cloudflare IP 回退及 HostResolverRules 映射。图片和普通页面共用此传输层，均跟随实时 DNS/CDN；本轮并未修改图片地址或正文解析。
- 真机同时观察到主站发现页代理连接失败。对已确认的只读接口增加主站域名与官方 App 域名之间的回退；仅传输连接失败时触发，业务码、HTTP 错误及写操作不会切域名重发。图片 URL 仍使用服务器原始地址，不猜测替换图片主机。
- 领取后若未确认今日已领，先禁用按钮并要求刷新；若日序/周期还出现跳变，则当前 ViewModel 保持同日保护，直到读到已领取或新的服务端日期。该保护是页面级，不宣称为跨进程的服务端幂等保障。
- 移除临时接口对比信息及诊断输出，不记录登录凭据，不再尝试重复领取今日奖励。
